## 1. Executive Summary & Central Question Resolution

### The Central Question:
Does `git push origin HEAD:<pr_number>/merge` target GitHub's read-only `refs/pull/<number>/merge` namespace, or does it resolve to a branch under `refs/heads/`?

### The Authoritative Git Resolution Proof:
Under standard Git refspec syntax and behavior (verified empirically and per `git-push(1)` specification):
1. **Unqualified Destination Ref:** In `git push origin <src>:<dst>`, when `<dst>` does not begin with `refs/`, Git looks for an existing matching ref on the remote.
2. **Branch Namespace Default:** When `<dst>` does not already exist on the remote, Git defaults commit-ish destinations to the **`refs/heads/`** namespace.
3. **Exact Target Destination:** The command `git push origin HEAD:<pr_number>/merge` attempts to update or create:
   $$\mathbf{refs/heads/<pr\_number>/merge}$$
   **It does NOT target `refs/pull/<pr_number>/merge`.**
